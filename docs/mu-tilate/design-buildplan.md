# mu-Tilate build plan

Staged so every stage compiles, is tested without listening where it can be, and leaves the root build green. Started 2026-10-31 on Andy's go-ahead. Design: [design.md](design.md), [design-engine.md](design-engine.md), [design-ui.md](design-ui.md), [design-library.md](design-library.md). Stretch decisions: [stretch-prototype-results.md](stretch-prototype-results.md).

| Stage | Content | Checked by |
|---|---|---|
| 1 | `mu-tilate-layer` INTERFACE library and `mu-tilate-tests` console target in the root build. `SlicePlayer`: one monophonic slice at a time, native / re-pitch / reverse, fade in and out, cut fade into the next slice. **Done 2026-10-31.** | `mu-tilate-tests` (8 checks) |
| 2 | Slice model (`SliceList`, markers, pin flag) and the onset detector in `mu-core/Analysis` (spectral flux and SuperFlux, cached curve, peak picking by Sensitivity / Min gap, pre-roll, zero-crossing snap). **Done 2026-10-31**; the worker pool that runs it off the message thread is still to do (with stage 4). | `mu-tilate-tests` (18 checks) on synthetic loops |
| 3 | Stretch voice inside `SlicePlayer`: dry head, 5 ms cross-fade into a constant-rate Signalsmith Stretch (two stretchers, seeded, configured in `prepare`; default or short window), stretcher primed at the end of the first block (never `outputSeek` inline unless Strength is 0), zero-padded input at the slice end. **Done 2026-10-31.** Not yet done: staggering several layers that start on the same step (a layer-level job, stage 4), listening to the join. | `mu-tilate-tests` (27 checks): length, dry head exact, pitch and level, no leak from the next slice, zero allocation |
| 4 | **4a done 2026-10-31:** `Timeline` model (blocks, snap, place / move / copy / length / remove, original order, randomise) and `PhrasePlayback` (transport-anchored scheduler: block-size invariant, jump re-anchor, cut by next block or block length, Off / Re-pitch / Stretch ratios, zero allocation); `mu-tilate-tests` has 39 checks. Stretch needs the loop at the host sample rate: a layer keeps a windowed-sinc resampled copy beside the original (made when the loop is installed and when the host rate changes; the slices stay in the file samples). This was found when a 44.1 kHz drum loop played unstretched in a 48 kHz host: the processor demo render caught it. **4b first part done 2026-10-31:** `PhraseParams` (22 rows under `p{N}_`, including the shared insert) and the `MuTilateModDest` table with their checks (42 checks in all). **4b second part done 2026-10-31:** the `Phrase` layer (`Layer` subclass: bound parameters, modulation, the scheduler, the insert, retire tail; loop data published by a try-locked immutable `PhraseData`, voices dropped when it is replaced) and `LayerTypeId::Phrase` in mu-core; 49 checks, mu-core-tests (860) still pass. **4b third part done 2026-10-31:** saved state (`PhraseState`: slices with pins, blocks, loop reference as ValueTree children; `installLoop` / `commitEdit` / `writeExtras` / `applyExtras`), `mu_core::loadLoop` (file decode, `kMaxLoopBytes` cap checked before decoding, status message) and `PhraseAnalysis` (curve on a worker, slices from it with pinned markers kept, Even divisions); 57 checks. **Still to do in 4b:** the (`Layer` subclass, `PhraseParams`, ModTarget table, ValueTree state for slices and blocks), the staged swap at the loop boundary, the analysis worker pool, stagger of aligned stretch starts. | layer tests with hand-built `RenderContext` |
| 5 | **5a done 2026-10-31:** plugin target (VST3, CLAP, Standalone), `PluginProcessor` (+ preset file), `PluginEditor` on the shared shell with a first `PhraseContent` (Load loop, tempo mode, loop tempo, hold, strength, fades, level), `loadLoopAsync` (worker decode and detection, timeline laid out in source order), icon. The Standalone starts and shows the shared shell (screenshot checked). **Headless processor tests done** (60 checks): a WAV loads through `loadLoopAsync`, plays from the host transport, a saved session restores the loop by path with its slices and timeline, a missing file reports itself. **Stage 6 started 2026-10-31:** `mu_ui`-free shared `LoopWaveform` in mu-core (summary blocks, scroll, Ctrl+wheel zoom, draggable markers, double-click to add, Alt/right-click to delete, region select) wired into `PhraseContent`; marker edits publish through `commitEdit` and keep the timeline blocks on their slices (`Timeline::sliceInserted` / `sliceRemoved`). Screenshot checked with a real drum loop (Debug builds read `MU_TILATE_LOAD_LOOP` to load a loop at start). The timeline view (`PhraseTimeline`: ruler in bars and beats, blocks in the layer colour, click empty row to place the selected slice, drag to move with grid snap, Alt = free, Ctrl = copy, Delete removes) is in; a drag was checked on screen. **Still to do in 6:** slice player panel, block edge trimming, timeline zoom and scroll, playhead, tempo analysis (the loop tempo defaults to 120 and the Tempo knob sets it). **To do:** embedding the loop in a preset (today a session names it by path), pluginval on a Release build, factory presets. | screenshot; processor tests to come |
| 6 | UI: source waveform, slice markers, slice player, timeline, on the shared `mu-core` waveform, ruler and viewport. | screenshots |
| 7 | Sample library and factory loops, tempo analysis, mu-Tronic registry row, check-script and release wiring, manual. | per item |

**Status 2026-11-01 (stage 6):** done: onset detector with a running-median threshold (finds soft hits) and the detection controls with a Detect button; per-slice settings (`SliceSettings`, saved with the session) and their engine (pan, pitch, filter, amp and filter envelopes, loop, the pre-fade on a voice of its own); the slice player panel toggled with the waveform; timeline zoom, scroll, playhead paging and edge-drag length; loop tempo guessed from the length; 74 test results. Still to do in 6: a playhead on the waveform, status text for the two combo boxes, block left-edge trim (needs a start offset in the slice), the choke group and gate play mode (stored, not played), pad grid. Nothing has been listened to; demo renders (including the pre-fade) are in build/mutilate-demo.

Rules in force: shared code goes in `mu-core`; product symbols under `mu_tilate::`; no allocation in the audio thread; `check-layer-boundary.ps1` clean for this library.
